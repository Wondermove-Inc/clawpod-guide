# Manage notifications

<strong><span data-ui-label="notifications.page.title">Notifications</span></strong> shows notifications and your delivery preferences. These settings do not change other users' preferences or Agent execution policy.

## Delivery

1. Open <strong><span data-ui-label="notifications.page.title">Notifications</span></strong>.
2. Toggle <strong><span data-ui-label="notifications.settings.inAppNotifications">In-App Notifications</span></strong>.
3. In a supported browser, enable <strong><span data-ui-label="notifications.settings.pushNotifications">Push Notifications</span></strong> and approve the permission prompt.

Push depends on the browser and current origin's permission. Allow it separately on other devices or browsers. The toggle cannot be enabled if permission is denied or the environment is unsupported. Check operating-system notification blocks and browser site permissions too.

## Types

Administrators may see message, Agent error/lifecycle, security, system, Skill, and usage types. Tenant administrators may see member-related types; ordinary members may see only messages. Change only the types shown for your account.

Ensure alternative monitoring before disabling critical Agent or security alerts. Preferences do not delete original Agent, Task, or webhook events and execution records.

## History

Apply available type and severity filters, open an item to verify its linked target, and mark individual or all notifications read. The current Portal notification list has no delete button. Marking read does not change original Room, Task, Agent, or webhook data.
