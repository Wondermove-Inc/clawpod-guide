# Manage AI keys and credentials

A Credential profile in **AI Key Management** holds sensitive connection data for a model provider or local LLM. It is not a personal password vault or general-purpose secret store. Never copy its values into Chat, playbooks, documents, or logs. See [secret boundaries](./handle-secrets.mdx).

## Permissions and identity

Listing, creating, rotating, applying, and deleting can require different permissions. Tenant and platform super administrators may have role-based bypasses; other users need all relevant Credential and Agent actions. Seeing the screen does not grant access to every button.

Platform super administrators can filter profiles by tenant. When switching tenants, check the **tenant, provider, fingerprint, and number of connected Agents**, not just the key name.

## Register a credential

1. Open **AI Key Management → Add**.
2. Select provider and credential type.
3. Enter an identifiable name and the secret, then save.
4. Check provider, type, fingerprint, version, and connected Agent count.

Options include Claude API key or setup token, OpenAI API key, OpenAI Codex `auth.json`, Google Gemini API key, OpenRouter API key, Ollama server, and OpenAI-compatible local LLM server. Actual options depend on release and permissions.

Ollama takes a server address and model, not an API key. OpenAI-compatible local servers can accept an API key if needed. A successful connection test does not prove Agent runtime access; verify a non-sensitive prompt on the Agent too.

## Obtain provider API keys

ClawPod does not issue provider keys. Create one in your provider account or project, store it according to organization secret-handling procedures, and enter it only in the Credential input.

| Provider | Issuing console | Value for ClawPod |
| --- | --- | --- |
| Anthropic Claude | [Anthropic Console](https://console.anthropic.com/settings/keys) | API key; setup tokens can be stored but not bound to Agents |
| OpenAI | [OpenAI API keys](https://platform.openai.com/api-keys) | Project API key |
| Google Gemini | [Google AI Studio](https://aistudio.google.com/apikey) | Gemini API key |
| OpenRouter | [OpenRouter API keys](https://openrouter.ai/settings/keys) | OpenRouter API key |

Choose the intended organization/project and set minimum permissions, budgets, and billing with the provider. The **Official console** link opens the corresponding issuing page. Provider menus and billing terms can change, so fixed button sequences are not reproduced here.

The full value may not be shown again. Never paste it into Chat, Tasks, workspace files, screenshots, or support requests. If exposure is suspected, revoke the old key at the provider as well as replacing it in ClawPod.

## Create OpenAI Codex auth.json

OpenAI Codex uses the OAuth credential JSON created by a local Codex CLI login, not an ordinary OpenAI API key.

1. Install Codex CLI in a trusted personal development environment.
2. Run `codex login` and complete browser sign-in.
3. Open the generated `~/.codex/auth.json`.
4. Paste the **entire JSON** into the **OpenAI Codex** Credential input or the Agent creation Secrets configuration.

The input must be valid JSON with a top-level `tokens` object. Do not copy only part of the file or substitute `OPENAI_API_KEY`. ClawPod passes it through `OPENAI_CODEX_AUTH_JSON` and synchronizes the Agent's `~/.codex/auth.json` at runtime.

This file is an account credential and may include a refresh token. Keep it out of source control, shared drives, issues, Chat, and Skill packages. Do not obtain it using another person's session. After expiry or revocation, repeat sign-in with your own account and replace the credential.

## Connect an Agent

1. Select the Credential in the target Agent's settings.
2. Confirm the Agent and Credential belong to the same tenant.
3. Check for another credential conflicting in the same runtime slot.
4. Inspect whether application is updated, pending, or failed.
5. For pending or runtime warnings, check status and restart requirements, then verify a small request.

Claude setup tokens can be stored, but Agent binding accepts API keys only. To change provider or type, create a new profile and review the binding instead of assuming the old profile can be overwritten.

## Rotate safely

1. Issue a new secret at the provider.
2. Check the profile fingerprint and **Used by** Agent list.
3. Open the profile and enter the new value. Provider, type, and profile name cannot be changed in the rotation screen.
4. Verify application results and Agent count, then test affected Agents.
5. Revoke the old provider secret after the new connection works.

The Portal does not reveal stored raw secrets. It shows identifying fingerprints and current versions. If a value is lost, issue and replace it rather than trying to retrieve it.

## Disconnect and delete

A profile must have no connected Agents before deletion. Check **Used by**, replace or remove every binding, then delete. If deletion is rejected, check remaining bindings instead of repeatedly submitting.

Deleting a profile does not revoke the provider's API key. For exposure, departure, or contract termination, revoke it in the provider console too.

## Troubleshooting

Check the binding, Agent settings, restart state, then provider account, quota, and connectivity. If problems remain, inspect a safe test Room and Agent logs. For suspected exposure, rotate immediately and restart affected Agents.

Creation and rotation rights follow organization policy. Never request or share another member's secret. Encryption-key creation, rotation, and recovery are not verified customer Portal self-service features and are not documented here as operational procedures.
