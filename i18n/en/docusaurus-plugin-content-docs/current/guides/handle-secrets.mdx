# Handle secrets and sensitive values

The Portal has no general-purpose vault for arbitrary secrets to pass to Agents. Use each value's designated input.

| Value | Input | Boundary |
| --- | --- | --- |
| Anthropic, OpenAI, Codex `auth.json`, Gemini, OpenRouter, local LLM credentials | **AI Key Management → Credential** | Tenant-scoped profiles bound to Agents in the same tenant; see [credentials](./manage-credentials.mdx) |
| Provider credential entered directly for a new Agent | Creation **Secrets configuration** | One-time, per-Agent manual input; use a profile for shared rotation and revocation |
| Signing secret for incoming ClawPod webhooks | **Webhooks → Sources** | Plaintext may appear only during creation, regeneration, or rotation; see [webhooks](./send-webhook-to-agent.mdx) |
| Passwords, MFA codes, recovery codes, personal access tokens | Do not store in the Portal | Use organization secret storage, never Chat, workspace files, Tasks, or playbooks |
| URLs, project IDs, non-sensitive feature flags | Creation environment variables | Not a secret storage path; see [environment variables](./configure-agent-environment.mdx) |

## Provider credentials

Issue an Agent-specific credential in the provider's official console, register its provider and type in AI Key Management, bind it only to the intended same-tenant Agents, and test in a small Room. On exposure, departure, or contract termination, issue and apply a replacement and revoke the old value.

The Portal does not reveal stored raw credentials. Replace lost values rather than trying to retrieve them.

## Webhook signing secrets

A signing secret verifies incoming requests from a Source; it is separate from provider credentials.

1. Securely store the secret shown when creating the Source.
2. Enter the same value in the external service's webhook settings.
3. If exposure is suspected, rotate or regenerate the Source secret and immediately update the external service.
4. Send a test event to verify the new signature and delivery.

## Do not store secrets in ordinary content

Keep secrets out of `SOUL.md`, `AGENTS.md`, `TOOLS.md`, `MEMORY.md`, Chat, AI Chat, Task comments, meeting transcripts, Skill packages, webhook payloads, and custom environment variables. Do not register another user's `auth.json`, MFA recovery code, or browser cookie. Do not use internal settings or APIs as a vault.

An internal per-Agent configuration path returns masked values, but it is not exposed in the Portal. Do not call it directly or treat it as general secret storage.

:::warning
Do not ask an Agent to remember a secret or read an environment value into Chat. Connect provider access through Credential bindings and request only success or failure status, not the value itself.
:::
