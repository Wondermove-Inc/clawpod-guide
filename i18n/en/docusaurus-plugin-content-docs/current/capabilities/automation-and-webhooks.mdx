# Automation and webhooks

Use **Automations** to start Agent work from external events, schedules, or chat messages. Available creation and editing actions depend on your permissions and the target Agents and chats.

## Automation types

| Type | Trigger | What to configure |
| --- | --- | --- |
| Webhook | An event from an external service | Connection, event conditions, recipients, and playbook |
| Schedule | A specified time or repeating schedule | Daily, weekly, hourly, or a custom cron expression; displayed time zone; Agent; report chat; work instructions |
| Message | A matching message in a watched chat | Watched chat; contains, equals, or starts-with text condition; Agent; report chat; work instructions |

## Ask an Agent to create one

In a conversation, describe the trigger, work, and where to report the result. You can also choose **Automations → Create automation → Create with an agent** and select a chat.

> Every Monday at 9 AM, summarize this week's work and report it here. Confirm the time zone and ask for any other details you need.

> Create an automation that checks the situation and reports here when a message containing “deployment failed” arrives in this chat.

The Agent checks the information needed and configures or proposes the automation using available tools and permissions. For webhook proposal approval and external service registration, follow [the webhook guide](../guides/send-webhook-to-agent.mdx). Check the actual enabled state and remaining setup steps rather than assuming your request activated it.

## Create one directly

1. Open **Automations → Create automation → Create manually**.
2. Choose **Webhook**, **Schedule**, or **Message**. Types unavailable under your permissions cannot be selected.
3. Enter a name and trigger. For a schedule, check the displayed time zone; for messages, select the watched chat and text condition.
4. Set the work instructions, Agent, and report chat, or the webhook recipients. Use the available Agent and chat choices.
5. After creation, check its enabled state in the list. It may remain off if setup is incomplete or the Agent did not answer its readiness check. Continue the setup check as instructed.

For webhooks, register the receiving URL and any required secret with the sending service, then send a test event. Saving the configuration alone does not confirm event delivery.

## Review and edit

Open an item in the list to inspect its trigger, instructions, and report destination. With permission, you can enable, disable, or delete it. **Ask the Agent in chat to change a schedule automation.** For message and webhook automations, use the editing controls available on their detail screens.

If a playbook is shared, saving it can affect other automations. Choose between changing only this automation and applying the change to all affected automations in the confirmation screen. Changing only this one requires permission to create a playbook copy.

## Check execution results

Review states such as queued, running, completed, execution failed, or report failed, and check the actual reply in the report chat. **Execution failure and report failure are different.** Check whether work already ran before repeating it. Also distinguish skipped runs due to pause or unmatched conditions from access problems.

Disable or delete automations you no longer need. Deletion cannot be undone, so review the configuration and any results you need first.

## Heartbeat and Tasks

[HEARTBEAT.md](../guides/configure-heartbeat.mdx) contains periodic check instructions; [Tasks and Milestones](../guides/use-tasks-and-milestones.mdx) track work and due dates. To run work at a specific time, configure and enable a schedule automation. Writing a file or a due date alone does not schedule execution.
