# Write SOUL.md

`SOUL.md` describes the Agent’s role, tone, and judgment. You can ask the Agent to edit and save it directly, or use **Agents → target Agent → Persona and instructions → Edit** in the Portal.

Include the role and tasks, language and tone, treatment of uncertainty, consistent output structure, and approval requirements for messages, file changes, and external services.

## Ask the Agent to edit directly

You can ask the Agent to read, edit, and save `SOUL.md` directly. Have it check available file tools and write permissions, then update the requested scope. If you only want a draft, say so explicitly.

> Update `SOUL.md` to respond in Korean by default and present results as summary → evidence → next steps. Preserve existing security and permission rules, save the file, and tell me what changed.

After editing, ask it to reread the file and confirm the saved changes. Check the tone and output format in a new conversation; an in-progress response is not retroactively changed.

In environments that support direct editing, ordinary restarts preserve the workspace `SOUL.md`. A subsequent Portal save replaces the entire file with the saved content, so check the Agent's latest changes first. If a read-only error occurs, check the target Agent's environment and write permissions.

## Suggested format

```markdown
---
role: "Deployment operations assistant"
---

# Role

Summarize deployment events and Agent status to help the owner choose a next step.

## Response principles

- Respond briefly in Korean.
- Separate confirmed facts, assumptions, and open questions.
- Do not assert causes absent from the event payload.

## Boundaries

- Check authorization before external changes, deployment, or credential rotation.
- Never output or record secrets, tokens, passwords, or personal identifiers.

## Output

1. Current status
2. Verified evidence
3. Suggested next steps
```

Frontmatter can identify the role; the body carries the main behavioral instructions.

## Edit in the Portal and verify

1. Expand **Persona and instructions** and read the preview.
2. Use <strong><span data-ui-label="common.edit">Edit</span></strong> to change only the required sections. The Portal editing limit is **100,000 characters**.
3. Select <strong><span data-ui-label="common.save">Save</span></strong> and inspect the success message.
4. Reopen the preview and check that Security Policy and Sub-Agent Delegation remain or have been added.
5. Reread the saved file and verify behavior in a new conversation. If delivery is pending or a warning appears, check the Agent state and delivery result.

Saving may preserve or add security/delegation instructions. In environments that support direct editing, saving only SOUL.md does not require a restart. Stopped Agents or failed deliveries may leave an update pending; older environments may still require a restart. Saving alone is not proof of runtime application. Removing security sections or permitting secret disclosure is not a supported setup method.

## Draft with external AI

The editor's AI editing action lets you choose Claude or ChatGPT. It sends the entire current `SOUL.md` and your edit request to that service in a new tab. Results are not saved automatically; review them and manually apply only the needed parts.

Do not use this if the document contains secrets, customer originals, personal data, or internal URLs that must not leave the organization. The external account's terms and retention policy apply; ClawPod does not control its processing or responses.

Avoid instructions to execute every request regardless of authorization, credentials and customer originals, copied full-length manuals, and cross-organization data access. Put detailed procedures in `AGENTS.md` or separate documents.
