# 기능 설치와 활성화

현재 Cloud에서 소비자가 추가로 준비하는 기능은 Credential, Marketplace Skill 요청, Webhook 세 종류입니다. Marketplace 요청이 실제 Skill package 설치·runtime 활성화까지 보장되지는 않습니다. channel·device·plugin을 이 절차로 활성화할 수는 없습니다. 자세한 경계는 [숨겨진 Agent 기능의 소비자 제공 상태](/capabilities/consumer-availability)를 따릅니다.

## 직접 설정 가능한 기능의 공통 순서

1. **기능 선택**: AI 키 관리, 에이전트 스킬, 웹훅 중 필요한 Portal 메뉴를 엽니다.
2. **권한 확인**: Credential 사용, Skill 설치 요청, Webhook 관리, 조직 데이터 접근에 필요한 역할을 확인합니다.
3. **연결 또는 요청**: 필요한 Credential, Skill 설치 요청 또는 Webhook source·rule·playbook을 연결합니다.
4. **범위 설정**: Agent가 접근할 수 있는 데이터, 대상, 실행 권한을 최소 범위로 설정합니다.
5. **동작 확인**: 테스트용 입력으로 결과와 권한 범위를 확인합니다.
6. **중지·제거 준비**: 사용하지 않을 때 연결, credential binding, 접근 권한을 해제하는 방법을 기록합니다.

## 기능 문서에서 확인할 항목

| 항목 | 확인하는 이유 |
| --- | --- |
| 소비자 제공 경로 | Portal에서 직접 쓸 수 있는 기능인지 Agent 요청 기능인지 구분합니다. |
| 설치 또는 연결 대상 | 어떤 Credential, Skill, Webhook이 필요한지 알 수 있습니다. |
| 필요한 credential과 권한 | 개인 credential을 잘못 공유하거나 과도한 권한을 주는 일을 막습니다. |
| 사용자 확인 또는 승인 | 외부 전송, 파일 변경, 브라우저 작업처럼 검토가 필요한 동작을 구분합니다. |
| 제거와 복구 | 기능을 중지할 때 남는 연결과 데이터 영향을 확인합니다. |

## Agent에게 기능을 물어볼 때

Agent는 기능을 추천하거나 설정 방법을 안내할 수 있지만, 사용자의 권한을 넘어서 기능을 설치하거나 credential을 공유해서는 안 됩니다. Agent에게는 다음처럼 질문하세요.

> 이 요청은 현재 Agent에게 가능한가요? 준비된 Skill·MCP·Credential과 접근할 데이터 범위를 먼저 알려 주세요. 아직 실행하지는 마세요.

Agent의 답변에는 기능 문서 링크와 필요한 권한·설정 조건이 함께 있어야 합니다.
