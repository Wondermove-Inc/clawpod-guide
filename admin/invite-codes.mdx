# 초대 코드 관리

**<!-- ui-label: inviteCodes.title -->초대 코드<!-- /ui-label -->**는 새 workspace 가입에 쓰는 코드입니다. 기존 tenant 또는 조직에 멤버를 초대하는 기능이 아닙니다. 정상 redemption은 코드의 plan으로 새 tenant를 만들고 가입자를 테넌트 관리자로 활성화합니다. 현재 화면은 플랫폼 최고 관리자 경계이며, 코드 생성에는 `platform:invite:Create` 권한이 필요합니다.

## 코드 만들기

1. **<!-- ui-label: inviteCodes.title -->초대 코드<!-- /ui-label --> → <!-- ui-label: inviteCodes.generateCode -->코드 생성<!-- /ui-label -->**을 엽니다.
2. 적용할 plan, 최대 사용 횟수, 만료 일수를 정하고 **<!-- ui-label: inviteCodes.generateCode -->코드 생성<!-- /ui-label -->**을 선택합니다.
3. 한 번만 쓸 코드인지 여러 사람이 쓰는 코드인지 명확히 표시합니다. 현재 최대 사용 횟수에 `0`을 입력해도 생성 요청에서는 `1`로 처리되므로, 무제한 코드로 안내하지 마세요.
4. 생성 뒤 코드를 복사하거나 초대 이메일을 보냅니다. 여러 번 사용할 수 있는 코드를 **<!-- ui-label: inviteCodes.sendEmail -->이메일 발송<!-- /ui-label -->**할 때는 추가 경고를 확인한 뒤 수신자 이메일을 입력합니다.

공유 코드에는 전달 범위가 넓어질 위험이 있습니다. 특정 고객 한 명을 위한 초대라면 최대 사용 횟수를 1회로 제한하고, 만료일을 짧게 설정하세요.

## 상태 확인과 회수

목록에서 plan, 사용 횟수, 만료 시점, 활성 상태를 확인합니다. 잘못 보냈거나 더 이상 사용되면 안 되는 코드는 행의 **<!-- ui-label: inviteCodes.revokeConfirm -->폐기<!-- /ui-label -->**를 누른 뒤 확인 창에서 다시 **<!-- ui-label: inviteCodes.revokeConfirm -->폐기<!-- /ui-label -->**를 선택해 비활성화합니다. 회수는 새 사용을 막기 위한 조치이며, 이미 가입한 사용자·tenant·권한을 자동으로 되돌리는 작업으로 안내하지 않습니다.

## 운영 확인 목록

- 코드가 의도한 plan에 연결되어 있는가
- 최대 사용 횟수와 실제 사용 횟수가 맞는가
- 만료 전 재발급 또는 회수가 필요한가
- 재전송 이메일의 수신자가 맞는가

초대 코드는 IAM Policy를 대신하지 않습니다. 기존 조직에 사용자를 넣으려면 Organization 멤버 추가 흐름을 사용하고, 새 workspace의 Agent 접근도 필요한 최소 권한으로 설정하세요.
