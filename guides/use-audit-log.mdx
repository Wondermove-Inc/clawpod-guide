# Audit Log 확인과 내보내기

Audit Log는 권한, Agent, 설정 등 중요한 변경을 조사할 때 사용하는 기록입니다. 로그를 볼 수 있는 권한과 export 권한은 별도로 제한될 수 있습니다.

## 기록 찾기

1. Portal에서 **Audit Log**를 엽니다.
2. 날짜, event type, Agent, severity 등으로 결과를 좁힙니다.
3. 필요한 항목을 열어 이벤트별 상세 정보와 처리 결과를 확인합니다.

조사할 때는 먼저 시간 범위와 대상 조직·Agent를 좁히세요. 넓은 범위의 로그를 무분별하게 내보내면 다른 사용자의 운영 정보가 포함될 수 있습니다.

## 내보내기

필터링한 결과가 있을 때 CSV 또는 JSON 형식으로 내보낼 수 있습니다.

1. 필요한 필터를 적용합니다.
2. 화면의 결과 수와 범위를 다시 확인합니다.
3. **CSV** 또는 **JSON**을 선택합니다.
4. 승인된 보관 위치에 저장하고, 공유 대상과 보존 기간을 기록합니다.

내보낸 파일은 데이터 접근 권한을 가진 운영 자료로 취급하세요. Chat Room이나 공개 issue에 업로드하지 말고, 조사 종료 후 조직의 보존 정책에 따라 폐기합니다.

## 운영 확인 항목

- 어떤 사용자가 어떤 action을 수행했는지
- 어떤 resource와 조직 범위에 영향이 있었는지
- 변경 전후 값에 민감한 정보가 포함됐는지
- 후속 조치가 권한 회수, credential 교체, Agent 재시작 중 무엇인지

Audit Log는 조사를 돕는 기록이며 자동 rollback 기능은 아닙니다. 되돌리기 전에 현재 설정과 영향을 받는 사용자·Agent를 별도로 확인하세요.

## 필터와 결과 해석

날짜·시간대, 이벤트 유형, 사용자·Agent, 심각도로 범위를 좁히고 누가 어떤 대상에 어떤 작업을 했는지와 결과를 함께 확인하세요. 세부 정보는 이벤트 종류에 따라 다르며 모든 항목에 변경 전후 값이 있는 것은 아닙니다. 삭제된 대상도 기록에 식별 정보가 남을 수 있습니다.

페이지 이동과 내보내기는 같은 조회 기준을 유지합니다. 새 기록을 확인하려면 새로고침하고, 필터나 조회 범위를 바꾼 뒤에는 내보내기 범위를 다시 확인하세요. 조회·상세·내보내기 권한은 서로 다를 수 있으며, 내보내기 한도나 권한 오류가 나오면 범위를 줄이거나 관리자에게 문의하세요.
