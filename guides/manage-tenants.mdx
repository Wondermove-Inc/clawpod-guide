# Tenant 관리

이 문서는 **플랫폼 최고 관리자 전용**입니다. 테넌트는 조직·사용자·Agent·요금제의 상위 격리 경계이므로, 일반 조직 운영 문제를 테넌트 변경으로 해결하면 안 됩니다.

## Tenant 목록과 상태

Portal의 **<!-- ui-label: nav.tenants -->테넌트 관리<!-- /ui-label -->**에서 tenant를 검색하고 plan·status로 필터링할 수 있습니다. 목록에는 tenant별 조직 수와 멤버 수가 함께 표시될 수 있습니다.

변경 전에는 대상 tenant의 이름과 slug, 현재 plan, status, 영향받는 조직·사용자·Agent 수를 확인하세요. 유사한 이름만으로 tenant를 식별하지 마세요.

## Tenant 만들기

1. **<!-- ui-label: nav.tenants -->테넌트 관리<!-- /ui-label --> → <!-- ui-label: tenants.createTenant -->테넌트 생성<!-- /ui-label -->**을 선택합니다.
2. 이름을 입력하고 자동 제안된 slug를 검토합니다.
3. 할당할 plan 하나를 선택하고 tenant 격리 경계와 onboarding 책임자를 확인합니다.
4. **테넌트 생성**을 선택합니다.
5. 생성 뒤 대상 tenant에서 조직과 관리자 설정이 정상인지 확인합니다.

새 tenant의 plan은 사용자·조직·Agent quota와 기능 접근에 영향을 줄 수 있습니다. 고객별 예외를 global default로 승격하지 마세요.

## 탈퇴 요청 복원과 삭제

Tenant 삭제는 고위험 작업입니다. 삭제 전에는 계약·보존 기간·조직과 Agent 중지 영향·rollback 책임자를 확인해야 합니다.

삭제는 대상 행의 **테넌트 삭제**를 누른 뒤 확인 창에서 **테넌트 삭제**를 다시 선택해 실행합니다. 복원 버튼은 `withdrawal_pending` 상태의 tenant에만 표시되며, **테넌트 복원**과 확인 창의 재승인이 필요합니다. 삭제된 tenant를 복원하는 Portal 흐름은 현재 없습니다. 탈퇴 요청을 복원하기 전에는 고객 요청·보안 이슈·영향을 확인하고, 삭제나 복원을 운영 장애의 즉흥적인 해결책으로 사용하지 마세요.
