# Agent 상태와 설정 관리하기

이 가이드는 이미 생성된 Agent를 안전하게 운영하는 기본 절차입니다. 보이는 제어와 상세 섹션은 권한과 Agent 상태에 따라 달라질 수 있습니다.

## 1. Agent 찾기

1. Portal에서 **에이전트**를 엽니다.
2. 이름, 역할 또는 상태로 대상 Agent를 찾고, 필요하면 상태나 미배정 Agent 필터를 사용합니다.
3. Agent를 선택해 상세 화면을 엽니다.

목록의 상태는 운영 판단의 출발점입니다. 실행 중인지, 중지됐는지, 오류가 있는지 먼저 확인한 뒤 조치하세요.

## 2. 상세 정보 점검하기

상세 화면에는 환경에 따라 다음 정보가 표시될 수 있습니다.

- Desktop 또는 원격 Desktop
- Dashboard와 사용량 지표
- Conversations
- Metrics
- Overview와 Config
- Logs

문제가 있을 때는 바로 재시작하기보다 Overview, Config, Logs를 함께 확인하세요. Agent가 기대한 조직, 모델, credential, workspace 설정을 사용 중인지와 최근 오류를 구분하는 데 도움이 됩니다.

## 3. 시작·중지·재시작

Agent 상세 화면 하단의 제어에서 상태에 맞는 작업을 선택합니다.

- **Start**: 중지된 Agent를 다시 실행합니다.
- **Stop**: 실행 중인 Agent를 중지합니다.
- **Restart**: 실행 환경을 다시 시작합니다.

이 작업에는 Agent 수정 권한이 필요합니다. 실행 중인 작업이나 대화에 영향이 있을 수 있으므로, 운영 Agent는 Room에 공지하고 현재 작업이 끝났는지 확인한 뒤 중지 또는 재시작하세요.

## 4. 설정 또는 Credential을 바꾼 뒤

현재 Config 화면의 `SOUL.md` 편집은 ConfigMap 갱신과 Agent restart를 시도합니다. 성공 메시지만으로 restart 완료를 단정하지 말고 warning 또는 `restartFailed`를 확인한 뒤 Agent 상태와 test Room으로 검증하세요. Credential, resource, image처럼 deployment-backed 변경의 재시작 필요성은 해당 화면의 안내를 따르세요.

권장 순서:

1. 변경 대상과 영향받는 Agent를 확인합니다.
2. 안전한 시간에 변경을 저장합니다.
3. 화면이 재시작을 안내한 변경만 필요한 Agent에 적용합니다.
4. Agent 상태와 Room의 작은 요청으로 정상 반영을 확인합니다.
5. Logs와 Metrics에 오류가 없는지 확인합니다.

## 5. 삭제 전 확인

**Fire** 또는 삭제 작업은 되돌릴 수 없는 운영 변경일 수 있습니다. 삭제 전에는 다음을 확인하세요.

- 이 Agent가 Room, webhook rule, scheduled task 또는 설치된 Skill의 대상인지
- 필요한 workspace 문서나 산출물이 보존됐는지
- 대체 Agent와 담당자가 준비됐는지

삭제 권한도 Agent 수정 권한 범위에 의해 제어됩니다. 권한이 없거나 영향 범위를 확신할 수 없으면 조직 관리자에게 요청하세요.
