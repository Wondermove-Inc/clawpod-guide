# 채팅 모드 선택과 맞춤 설정

채팅 모드는 같은 Agent에게 일을 맡길 때 현재 요청을 어떤 방식으로 처리할지 정하는 기능입니다. [Chat Room](./use-chat-room.mdx)의 입력창에서 **채팅 모드**가 표시되는 환경에서 사용할 수 있습니다.

## 어떤 모드를 선택할까요?

| 모드 | 사용할 때 | 요청 예시 |
| --- | --- | --- |
| 기본 | 질문, 요약, 변경 작업 등 요청한 내용을 처리할 때 | “이 문서를 요약해줘.” 또는 “이 문서의 제목을 바꿔줘.” |
| 논의 | 근거를 조사하고 요구사항·대안을 정리해 계획을 만들 때 | “보고서들을 어떻게 정리하면 좋을지 먼저 검토해줘.” |
| 실행 | 정해진 작업을 체계적으로 수행하고 결과를 검증할 때 | “정한 기준대로 보고서를 정리하고 누락이 없는지 확인해줘.” |

**기본 모드에서도 실제 변경 작업이 가능합니다.** 수정하려고 반드시 실행 모드를 선택할 필요는 없습니다. 실행 모드는 작업 관리·검토·후속 확인 등을 포함해 체계적으로 일을 진행하도록 지시하는 방식입니다.

논의 모드는 조사와 계획에 집중하며 변경은 계획 문서 등 계획을 위한 결과물로 한정합니다. 계획을 실제 작업으로 옮기려면 기본 또는 실행 모드로 전환해 요청하세요.

## 모드 선택하고 메시지 보내기

1. 채팅 입력창의 **채팅 모드** 메뉴에서 기본·논의·실행을 선택합니다. 입력창에서 `Shift+Tab`으로 전환할 수도 있습니다.
2. 필요한 경우 **맞춤 설정**을 열어 해당 모드의 세부 설정을 조정합니다. 잘 모르겠다면 **자동**으로 두세요.
3. 작업 요청을 입력하고 메시지를 보냅니다.

**모드를 바꾸기만 해서는 작업이 시작되지 않습니다.** 선택한 모드와 설정은 다음 메시지를 보낼 때 함께 적용됩니다. 이미 진행 중인 작업이 모드 선택만으로 중단되거나 다시 시작되는 것으로 생각하지 마세요.

설정은 현재 브라우저에서 사용자·대화방별로 저장됩니다. 다른 브라우저나 대화방에서도 같은 설정일 것이라고 가정하지 말고 전송 전에 확인하세요.

## 논의한 내용을 실행으로 이어가기

먼저 **논의** 모드에서 다음처럼 요청합니다.

> 이 보고서들을 분류하려고 해. 현재 자료를 확인하고 분류 기준과 작업 계획을 정리해줘.

질문에 답하고 계획을 정한 뒤 **실행** 모드로 바꿔 다음 메시지를 보냅니다.

> 앞에서 정한 기준대로 보고서를 분류하고, 누락되거나 중복된 항목이 없는지 확인해줘. 결과는 이 대화방에 정리해줘.

간단한 작업은 기본 모드에서 바로 요청해도 됩니다. 모든 요청을 논의와 실행의 두 단계로 나눌 필요는 없습니다.

## 맞춤 설정

### 공통: 추가 지시

각 모드에 최대 **240자**의 추가 지시를 입력할 수 있습니다. 해당 모드에서 메시지를 보낼 때마다 함께 전달되므로 반복 적용할 내용만 넣으세요.

> 결과는 한국어로 작성하고, 변경한 항목과 검증 결과를 포함해줘.

일회성 요청은 채팅 본문에 적고, 비밀번호나 API 키는 추가 지시에 넣지 마세요.

### 논의: 논의 깊이

| 설정 | 동작 |
| --- | --- |
| 자동 | Agent가 대화에 맞춰 논의 깊이를 정합니다. |
| Lite | 꼭 필요한 질문만 하고 빠르게 계획합니다. |
| Deep | 주요 결정을 질문하고 대안을 비교합니다. |
| Full | 한 번에 한 질문씩 함께 폭넓게 탐색합니다. |

### 실행: 작업 관리 도구

| 설정 | 동작 |
| --- | --- |
| 자동 | 작업에 맞는 기록·관리 방식을 Agent가 선택합니다. 별도 작업 기록이 불필요할 수도 있습니다. |
| Tasks | 공유 프로젝트에 작업을 등록하고 담당자와 진행 상황을 관리합니다. [태스크와 마일스톤](./use-tasks-and-milestones.mdx)을 참고하세요. |
| Workboard | Agent의 작업 보드에 카드를 등록하고 실행 상태를 관리합니다. |

단일 작업으로 처리할지, 순차·병렬로 나눌지 등 실행 방식은 Agent가 작업에 맞춰 선택합니다. 작업 관리 도구를 선택하는 것과 병렬 실행을 지정하는 것은 다릅니다.

### 실행: 검토 조건

- **자동:** 작업의 성격과 위험도에 따라 독립 검토 여부를 결정합니다.
- **필수:** 독립 Agent가 결과를 검토하도록 지정합니다.

검토를 수행할 수 없는 상황이라면 검토 완료로 처리하지 말고 남은 조건과 이유를 확인하세요.

### 실행: 진행 확인

**자동**은 대기 작업에 맞춰 다시 확인할 시점을 정합니다. **5분·10분·30분**을 선택하면 대기 중인 작업을 지정한 시간 후 다시 확인하도록 요청합니다.

모든 작업을 그 주기로 반복 실행하는 예약 기능은 아닙니다. 설정만으로 후속 확인이 완료된 것도 아니므로, 실제 진행 상태와 결과는 Agent의 보고로 확인하세요.

### 실행: 승인 방식

| 설정 | 의미 |
| --- | --- |
| 자동 | 사용자 지시와 적용되는 스킬·워크플로의 승인 규칙을 따릅니다. |
| 승인 범위 내 | 명시적으로 승인된 범위에서 진행합니다. 작업과 영향이 승인된 위험 작업도 포함할 수 있습니다. |
| 위험 시 확인 | 승인된 범위라도 위험 작업 직전에는 다시 확인합니다. |

모드나 승인 방식 선택만으로 도구 권한·조직 접근 권한이 늘어나거나 요청하지 않은 외부 작업이 승인되지는 않습니다. 대상과 변경 범위를 메시지에 명확히 적으세요.

실행 모드는 요청한 작업의 완료와 검증을 목표로 합니다. 필요한 권한·도구가 없거나 외부 승인이 대기 중이라면 완료를 보장하지 않으며, 현재 대화방에서 확인된 결과와 남은 작업을 확인하세요.
