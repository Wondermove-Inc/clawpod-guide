# Agent에게 Browser와 CLI 작업 요청하기

Browser control은 full Agent image, CLI 작업은 full 또는 lite Agent image에서 사용합니다. image 선택은 플랫폼 최고 관리자가 제어합니다. 일반 사용자는 사용 가능한 full image가 기본 선택되며, 생성 후 lite image이거나 browser readiness 확인이 실패할 때만 플랫폼 최고 관리자에게 조정을 요청하세요. `clawpod/agent-lite`에는 Chromium, X11 Desktop, VNC/noVNC가 없으므로 GUI browser 작업용으로 만들지 않습니다.

`cli-anything` Skill은 full과 lite image에 기본 포함되며, boot 중 `/workspace/skills/cli-anything`에 준비됩니다. 특정 CLI package나 외부 service가 필요한 Skill은 package의 `SKILL.md`에 적힌 dependency와 credential을 먼저 설정합니다.

## Browser 작업 요청

Browser 작업은 페이지 열기, 탐색, 입력, 클릭, snapshot, screenshot, 파일 upload·download처럼 실제 browser 조작을 포함합니다. full image Agent는 Playwright MCP로 browser를 조작하고, desktop Skill로 GUI desktop을 조작할 수 있습니다. 요청에는 다음을 넣으세요.

1. 대상 URL과 업무 목적
2. 읽기만 할지, 입력·클릭까지 할지
3. 사용할 계정 또는 browser profile의 범위
4. 제출, 구매, 전송, 다운로드 전 사용자 확인 필요 여부
5. 결과로 받을 내용: URL 목록, 요약, screenshot, 다운로드 파일 등

예시:

> `https://example.com/reports`에서 이번 주 보고서 목록만 확인해 주세요. 로그인·입력·다운로드·외부 전송은 하지 말고, 제목과 URL만 표로 정리해 주세요.

Cloud는 전용 browser profile의 생성·선택·회수 lifecycle을 제공하지 않습니다. 기존 Agent browser state, cookie, 다운로드 파일을 민감한 데이터로 취급하고 개인 일상 browser profile·password manager를 공유하지 마세요. 결제, 계정 변경, 메시지 전송, 파일 upload·download는 되돌리기 어렵거나 데이터가 외부로 나갈 수 있으므로 실행 직전에 다시 확인하도록 요청하세요.

## CLI·파일 작업 요청

filesystem MCP의 작업 root는 `/workspace`이며, full·lite image 모두 `cli-anything` Skill을 제공합니다. 다만 wrapper가 구성하는 실행 도구는 `/root`, `/tmp`도 접근 가능한 구성일 수 있습니다. 따라서 요청과 `AGENTS.md`에 허용 경로를 명시하세요. `cli-anything`은 GUI application 또는 source repository용 CLI harness를 만들고, 다듬고, test하는 작업에 사용합니다. 이 Skill은 `python3`가 필요하며, LibreOffice·Chromium·ffmpeg처럼 full image에만 있는 실제 프로그램을 대상으로 하면 full image Agent를 사용합니다.

요청하기 전에 대상 workspace와 기대 결과를 제한하세요.

> `/workspace/project` 안에서만 작업해 주세요. 먼저 실행할 명령과 변경할 파일 목록을 보여 주세요. network 접근·package 설치·삭제·Git push는 하지 말고, 검사 결과만 알려 주세요.

수정이 필요하면 계획과 실제 변경을 분리합니다.

1. **검사 단계**: 명령, 읽을 파일, 예상 출력만 제시하게 합니다.
2. **승인 단계**: 바뀔 파일과 외부 영향이 맞는지 검토합니다.
3. **실행 단계**: 허용한 경로에서만 실행하게 합니다.
4. **검증 단계**: 변경 파일, 실행한 검증, 실패·미실행 항목을 받습니다.

`rm`, credential 변경, package 설치, deployment, Git push, 외부 API 호출처럼 파급이 큰 명령은 요청에 명시적으로 포함시키고, Agent가 실행 전 다시 확인하도록 하세요.

## 결과물 받기와 정리

Agent의 `/workspace` 파일을 Portal Documents에서 미리보기·다운로드하는 고객용 경로는 현재 확인되지 않았습니다. 결과물을 받아야 하면 Agent에게 Chat artifact로 전달하거나 Chat·Task 첨부로 올리도록 요청하고, 내려받기 전 파일명·내용을 확인하세요. 필요 없어진 민감 결과물과 browser 다운로드는 조직의 보존 정책에 따라 정리합니다.

작업 요청과 확인은 **Chat**에서 대상 Agent가 참여한 Room을 열어 진행하세요. Agent 상세의 **Conversations**는 읽기 전용 기록 화면이므로 작업 요청을 보내는 곳이 아닙니다.

작업 실패 시에는 raw credential, browser cookie, 전체 terminal log를 공유하지 마세요. 실행한 단계, 대상 URL 또는 workspace 경로, 오류의 비민감 요약, Agent 상태만으로 먼저 진단합니다.
