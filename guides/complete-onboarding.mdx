# 새 workspace 온보딩 완료하기

새 workspace가 온보딩 상태라면 Portal은 `/onboarding`에서 회사 정보 분석과 초기 Agent 준비 흐름을 엽니다. 이 과정은 일반 Agent 생성 화면과 별개입니다.

## 진행 순서

1. **<!-- ui-label: onboarding.startButton -->시작하기<!-- /ui-label -->**를 선택하고 회사명, 주요 비즈니스 도메인을 차례로 입력합니다. 각 화면의 **<!-- ui-label: onboarding.continueHint -->계속<!-- /ui-label -->**을 선택합니다.
2. 회사 홈페이지·경쟁사·참고할 에이전시 URL 중 안내된 URL을 입력하고, 필요하면 추가 요청사항을 작성합니다. 회사 URL 또는 경쟁사 URL 중 하나는 필수입니다.
3. 분석 완료 뒤 **<!-- ui-label: onboarding.viewResults -->분석 결과 보기<!-- /ui-label -->**로 회사 개요와 제안된 조직 구성을 검토합니다. 조직도에서 필요한 역할을 선택한 뒤 **<!-- ui-label: onboarding.confirmOrganization -->조직 확정<!-- /ui-label -->**을 선택합니다.
4. LLM provider를 선택하고 API key를 입력합니다. 화면이 key를 검증한 뒤 다음 단계로 진행합니다.
5. 연락처 번호를 입력·확인하면 **<!-- ui-label: onboarding.soulMdPreparing -->Soul.md 생성 준비 중...<!-- /ui-label -->**, **<!-- ui-label: onboarding.orgEstablished -->조직 설립 완료<!-- /ui-label -->**, **<!-- ui-label: onboarding.deployingAgents -->에이전트 배포 중...<!-- /ui-label -->** 순서의 준비 상태가 표시됩니다.
6. “AI 조직이 준비되었습니다” 완료 화면 뒤 Portal Chat으로 이동해 준비된 Agent를 확인합니다.

## 입력 전 확인할 점

- URL과 추가 요청은 분석에 사용됩니다. 고객 비밀, 비밀번호, API key, 계약 원문을 넣지 마세요.
- API key는 선택한 provider에 전달되어 유효성을 확인합니다. key 발급·보관은 [Credential 관리](/guides/manage-credentials)와 [Secret과 민감한 값 다루기](/guides/handle-secrets)를 따르세요.
- 일부 Agent 배포가 실패하면 **<!-- ui-label: onboarding.partialFailureWarning -->일부 에이전트 배포에 실패했습니다.<!-- /ui-label -->**와 **<!-- ui-label: onboarding.retryFailedAgents -->실패한 에이전트 재시도<!-- /ui-label -->**가 표시됩니다. 완료로 간주하지 말고 실패한 Agent만 재시도하거나 수동 설정으로 전환하세요.

<Note>
이 흐름이 보이지 않는 경우에는 새 workspace의 온보딩 상태가 아니거나, 가입 승인·권한 단계가 아직 끝나지 않았을 수 있습니다. 먼저 [가입, 로그인, 계정 복구](/guides/start-account)와 [첫 Agent 만들기](/start/first-agent)를 확인하세요.
</Note>
