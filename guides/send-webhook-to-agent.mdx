# Webhook으로 Agent에게 이벤트 보내기

이 가이드를 마치면 외부 서비스의 event를 지정한 Agent 또는 Chat Room으로 보낼 수 있습니다. signing secret과 verifier가 설정된 Source에서는 서명 검증을 거칩니다.

## 시작하기 전에

- Webhook source와 rule을 만들 권한이 필요합니다.
- event를 받을 조직, Agent 또는 Room을 미리 정합니다.
- 외부 서비스에서 HTTPS Webhook URL과 signing secret을 설정할 수 있어야 합니다.
- event payload에 고객 데이터가 포함될 수 있으므로, 수신 대상과 playbook 내용을 최소 범위로 정합니다.

## 1. Playbook 만들기

1. <strong><span data-ui-label="nav.webhooks">웹훅</span> → <span data-ui-label="webhooks.playbooks.title">플레이북</span> → <span data-ui-label="webhooks.playbooks.create">플레이북 생성</span></strong>을 선택합니다.
2. <strong><span data-ui-label="webhooks.playbooks.name">이름</span></strong>과 <strong><span data-ui-label="webhooks.playbooks.content">내용</span></strong>을 입력합니다. 필요하면 <strong><span data-ui-label="webhooks.playbooks.preview">미리보기</span></strong> 또는 <strong><span data-ui-label="webhooks.playbooks.split">분할</span></strong>로 Markdown 결과를 확인합니다.
3. 하단 <strong><span data-ui-label="webhooks.playbooks.createSubmit">플레이북 만들기</span></strong>을 선택하고, 플레이북 목록에 새 항목이 보이는지 확인합니다.

Playbook은 source와 rule에 각각 연결할 수 있으며, event 메시지에 함께 추가됩니다.

예: “배포 실패 event를 받으면 영향 범위를 요약하고, 확정되지 않은 원인은 추측하지 말고 필요한 확인 항목을 나열하세요.”

## 2. 연동 만들기

1. **웹훅 → 연동 만들기 → 직접 만들기**를 선택합니다.
2. 외부 서비스 종류, 이름, 수신 조직을 선택합니다. 필요에 따라 서명 검증·시크릿·속도 제한·플레이북을 설정합니다.
3. 첫 규칙도 함께 만들려면 이벤트 조건과 Agent 또는 Room 대상을 지정합니다.
4. 연동을 생성한 뒤 수신 URL과 표시된 서명 시크릿을 외부 서비스 설정에 등록합니다.
5. 연동 생성 결과와 규칙 생성 결과를 각각 확인합니다. 연동은 생성됐지만 규칙만 실패한 경우, 연동을 다시 만들지 말고 결과 화면에서 규칙을 재시도하세요.

**에이전트와 만들기**를 선택해 Agent가 있는 대화방에서 어떤 서비스의 어떤 이벤트를 받고 싶은지 설명할 수도 있습니다. Agent가 올린 제안은 검토한 뒤 적용합니다.

서명 시크릿은 생성·재생성·교체 때만 평문으로 표시될 수 있습니다. 문서나 Chat에 붙여 넣지 말고 조직의 비밀값 보관 절차에 따라 보관하세요.

## 3. Rule로 대상 정하기

1. **웹훅**에서 대상 연동을 열고, **규칙** 영역의 **규칙 생성**을 선택합니다.
2. <strong><span data-ui-label="webhooks.rules.name">이름</span></strong>, <strong><span data-ui-label="webhooks.integrations.title">연동</span></strong>, <strong><span data-ui-label="webhooks.rules.targetType">대상 유형</span></strong>을 고르고 필요한 event 조건을 추가합니다.
3. <strong><span data-ui-label="webhooks.rules.target">대상</span></strong>으로 Agent 또는 Room을 하나 이상 선택합니다.
4. 같은 유형의 대상을 둘 이상 고르면 배분 방식을 선택합니다. Agent는 **브로드캐스트·라운드 로빈·유휴 우선 배분** 중 하나를, Room은 **브로드캐스트·라운드 로빈** 중 하나를 선택합니다.
5. 필요하면 rule 수준 Playbook, cooldown, 시간당 제한을 설정합니다.
6. 하단 <strong><span data-ui-label="webhooks.rules.create">규칙 생성</span></strong>을 선택하고 웹훅 목록에 새 규칙이 보이는지 확인합니다.

Source와 대상 Agent·Room은 같은 tenant 안에 있어야 합니다. 조직 단위 분리는 rule을 만드는 운영자가 대상 Agent·Room을 정확히 선택해 관리합니다.

### 배분 방식 선택

Agent 대상을 둘 이상 선택하면 다음 세 가지 옵션 중 하나를 고릅니다.

| 옵션 | 동작 |
| --- | --- |
| 브로드캐스트 | 선택한 모든 대상에 이벤트를 전달합니다. |
| 라운드 로빈 | 대상에 순서대로 이벤트를 배분합니다. |
| 유휴 우선 배분 (Idle First) | 쉬고 있는 Agent를 우선 선택합니다. 모두 작업 중이면 전달 가능한 대상에 순서대로 배분합니다. |

Room 대상에는 브로드캐스트와 라운드 로빈이 제공됩니다.

유휴 우선 배분에서 활동 상태 조회에 실패하면 일반 라운드 로빈으로 처리될 수 있습니다. 작업 중인 Agent가 끝날 때까지 이벤트를 대기시키는 기능은 아니므로 이벤트 기록과 실제 응답을 확인하세요.

## 4. 테스트와 확인

외부 서비스의 test event를 보낸 뒤 다음을 확인합니다.

1. <strong><span data-ui-label="nav.webhooks">웹훅</span> → <span data-ui-label="webhooks.tabs.events">이벤트</span></strong>에 수신 event가 기록되는지
2. Agent target이면 Cloud가 해당 Agent용 webhook Room으로 event를 전달하는지와 Agent가 실행 가능한 상태인지
3. Room target이면 지정한 Room에 시스템 메시지가 나타나는지와 필요한 참여자가 있는지

Agent는 event의 source, rule, event ID, JSON payload, 연결된 Playbook 지침을 메시지로 받습니다.

## 중지·rotation·복구

- 새 event를 멈추려면 Source 또는 Rule을 inactive로 전환합니다.
- Secret이 노출됐다고 판단되면 Source에서 rotate 또는 regenerate하고 외부 서비스 설정도 즉시 바꿉니다.
- 삭제는 되돌릴 수 없을 수 있으므로 Source·Rule·Playbook 설정을 먼저 보관합니다.
- 현재 ingress에는 사용자 실행 replay endpoint나 자동 delivery retry가 확인되지 않았습니다. 실패 시 Event 기록, 대상 Room, Agent 상태를 확인한 뒤 외부 서비스를 통해 새 event를 보내야 할 수 있습니다.
