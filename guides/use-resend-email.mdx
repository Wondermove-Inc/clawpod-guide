# Resend로 이메일 보내기

Agent에게 Resend 연결을 요청하면 필요한 스킬 설치와 연결 절차를 안내받을 수 있습니다. 연결 후에는 일반 텍스트·HTML 이메일, 첨부파일, 수신자별 일괄 발송을 요청할 수 있습니다. 받은편지함 조회·정리는 [Google Workspace](./use-google-workspace.mdx)를 사용하세요.

## 채팅에서 시작하기

사용할 Agent와의 1:1 채팅방에서 다음처럼 요청하세요.

> 능력 레지스트리에서 `resend-email` 스킬을 설치하고 메일 발송 연결을 안내해줘.

능력 레지스트리는 Agent가 사용할 스킬과 실행 도구를 찾는 공개 저장소입니다. Agent는 현재 환경에서 설치할 수 있는지 확인하고 필요한 패키지를 준비합니다. 저장소를 찾지 못하면 [공식 능력 레지스트리](https://github.com/Wondermove-Inc/clawpod-capabilities) 주소를 함께 전달하세요.

**스킬 설치와 Resend 연결 완료는 다릅니다.** 설치 후에는 아래 연결 확인까지 진행하세요.

## 발신자 연결하고 테스트하기

1. 사용할 Resend 계정의 API 키와 발신 이메일 주소를 준비합니다.
2. Agent 안내에 따라 API 키를 해당 Agent의 시크릿 스토어에 등록합니다. 값 전달과 보관은 [시크릿 다루기](./handle-secrets.mdx)를 따르세요. 이미 등록했다면 값 대신 등록한 이름이나 참조 ID를 알려주세요.
3. Agent가 키의 유효성과 사용할 발신 주소의 도메인 인증 상태를 확인합니다. 도메인이 인증되지 않았다면 Resend에서 필요한 DNS 설정을 완료해야 합니다. 스킬의 연결 검사는 DNS를 직접 변경하지 않습니다.
4. 검증이 끝나면 Agent가 요청하는 테스트 수신 이메일 주소 하나를 알려주세요. Agent가 정해진 테스트 메일을 발송하고 접수 결과를 안내합니다.

테스트 결과가 **Resend의 발송 요청 접수**인지 확인하고, 실제 도착 여부는 수신함에서 확인하세요. 접수 성공만으로 받은편지함 도착까지 확인된 것은 아닙니다.

## 이메일 발송 요청하기

수신자, 사용할 발신 주소, 내용과 첨부파일을 구체적으로 지정하세요.

> 연결한 Resend 발신 주소로 담당자에게 이 보고서를 첨부해서 보내줘. 수신자는 내가 지정한 주소이고, 제목은 ‘주간 보고서’로 해줘.

발송 전에 내용을 직접 검토하고 싶다면 초안만 요청할 수 있습니다.

> 이 보고서를 소개하는 이메일 초안을 작성해줘. 지금은 발송하지 마.

여러 사람에게는 “이 수신자 목록에 각각 개별 메일로 보내줘”처럼 요청하세요. 일부만 실패했다면 성공한 수신자에게 중복 발송하지 않도록 실패 건만 확인해 다시 처리하도록 요청하세요.

## 연결이 안 되거나 해제하고 싶을 때

- **키 검증 실패:** Resend에서 키의 유효성과 필요한 권한을 확인하고, Agent에게 시크릿 교체와 재검증을 요청하세요.
- **발신 도메인 미인증:** Resend의 도메인 인증을 완료한 후 다시 확인하세요.
- **접수됐지만 메일이 보이지 않음:** 수신함·스팸함과 Resend의 발송 상태를 확인하세요. 곧바로 같은 메일을 반복 발송하지 마세요.
- **연결 해제:** Agent에게 해당 연결에 사용하는 시크릿 삭제를 요청하고, 키 자체를 폐기하려면 Resend에서도 취소하세요. 스킬 삭제만으로 외부 서비스의 키가 폐기되지는 않습니다.
