# Secret과 민감한 값 다루기

현재 Portal에는 임의의 비밀값을 저장해 Agent에 전달하는 범용 보관 기능이 없습니다. 비밀값은 목적에 맞는 전용 경로로만 관리해야 합니다.

## 어떤 경로를 써야 하나요?

| 값의 종류 | 사용할 경로 | 중요한 경계 |
| --- | --- | --- |
| Anthropic, OpenAI, Codex `auth.json`, Gemini, OpenRouter, Local LLM credential | **AI Key Management → Credential** | tenant 단위 credential profile로 저장하고 같은 tenant의 Agent에 연결합니다. [Credential 관리](/guides/manage-credentials)를 따르세요. |
| 새 Agent 생성 중 직접 입력하는 provider credential | Agent 생성의 **Secrets configuration** | Agent별 일회성 manual 입력입니다. 공유·교체·회수가 필요한 값은 이 경로 대신 Credential profile을 사용하세요. |
| 외부 서비스가 ClawPod Webhook에 요청할 때 검증하는 signing secret | **Webhooks → Sources** | 생성·재생성·rotation 때만 평문으로 표시될 수 있습니다. [Webhook 가이드](/guides/send-webhook-to-agent)를 따르세요. |
| 비밀번호, MFA code, recovery code, 개인 access token | Portal에 저장하지 않음 | ClawPod에 저장할 대상이 아닙니다. 조직의 비밀값 보관 절차에 따라 보관하세요. Chat, workspace 파일, task, playbook에 넣지 마세요. |
| URL, 프로젝트 ID, 비민감 feature flag | Agent 생성의 **환경 변수** | custom 환경 변수는 범용 Secret Store가 아니며 ConfigMap에도 전달됩니다. [환경 변수 설정](/guides/configure-agent-environment)을 따르세요. |

## Provider credential을 안전하게 연결하기

1. provider 공식 콘솔에서 Agent 전용 credential을 발급합니다.
2. **AI Key Management**에서 provider와 credential type을 선택해 등록합니다.
3. 같은 tenant의 대상 Agent에만 연결하고, 작은 test Room으로 동작을 확인합니다.
4. 노출·퇴직·계약 종료가 발생하면 provider에서 새 값을 발급해 Credential을 교체한 뒤 이전 값을 폐기합니다.

Portal은 저장된 raw credential을 다시 표시하지 않습니다. 값을 잃어버렸다면 조회를 시도하지 말고 새 값을 발급해 교체하세요.

## Webhook signing secret 회전하기

Webhook Source의 signing secret은 provider credential과 다릅니다. 외부 서비스가 보낸 요청이 해당 Source에서 왔는지 검증하는 값입니다.

1. Source를 만든 직후 표시된 secret을 조직의 비밀값 보관 절차에 따라 보관합니다.
2. 외부 서비스의 Webhook 설정에 같은 값을 넣습니다.
3. 노출이 의심되면 Source에서 rotate 또는 regenerate를 실행하고 외부 서비스 설정을 즉시 바꿉니다.
4. test event로 새 서명이 검증되고 event가 전달되는지 확인합니다.

## 금지 사항

- `SOUL.md`, `AGENTS.md`, `TOOLS.md`, `MEMORY.md`에 secret을 적지 않습니다.
- Chat, AI Chat, task comment, meeting transcript, Skill package, webhook payload에 secret을 붙여 넣지 않습니다.
- custom 환경 변수에 API key나 access token을 넣지 않습니다.
- 다른 사용자의 `auth.json`, MFA recovery code, browser cookie를 받아 Agent에 등록하지 않습니다.
- Kubernetes Secret, ConfigMap, 내부 환경 변수 API를 고객 Portal의 Secret Store로 취급하거나 직접 호출하지 않습니다.

## 참고: 현재 화면에 없는 Agent별 secrets 관리

Agent별 값을 가려 반환하는 설정용 내부 경로가 구현되어 있지만, 현재 Portal에서는 사용할 수 없습니다. 일반 비밀값 보관소로 쓰거나 직접 호출하지 마세요.

<Warning>
Agent에게 “secret을 기억해”, “환경 변수에서 값을 읽어 Chat에 보여줘”처럼 요청하지 마세요. Agent에게 필요한 provider 접근은 Credential binding으로 연결하고, 결과에는 값 자체가 아닌 성공·실패 상태만 보고하게 하세요.
</Warning>
